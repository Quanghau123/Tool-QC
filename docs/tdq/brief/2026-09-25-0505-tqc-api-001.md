## Hiểu & kiến thức

Đã đọc JUnit và HTML. Lỗi trực tiếp là assertion `$.hits.hits.0._source.errorMessage` yêu cầu tồn tại, trong khi document Elasticsearch có `status = 1` nhưng không có trường `errorMessage`. Testcase hiện khai báo `exists: true` cùng `oneOf: [null, ""]`, nên trường bị omit sẽ fail dù trạng thái xử lý thành công.

Source backend MTC hiện tại cho thấy `BookingCampaignCreatedStreamWorker` tạo log Elasticsearch thành công chỉ với `SteamMessage` và `Status = Successful`; `ErrorMessage` chỉ được gán trong nhánh exception với `Status = Failed`. Model khai báo `ErrorMessage` nullable. Lịch sử Git từ commit `f33739e26b` ngày 2026-06-23 cũng thể hiện contract này ngay từ lúc thêm ELK log. Vì vậy việc Elasticsearch omit `errorMessage` khi `status = 1` phù hợp với backend contract hiện tại; assertion bắt trường phải tồn tại là stale testcase contract, không phải bằng chứng backend xử lý thất bại.

Testcase là schema v2, destructive, gồm 15 bước và đi qua PostgreSQL Booking, PostgreSQL MTC, Redis lifecycle, Elasticsearch log và callback thật. Lỗi nằm ở bước 11; các bước 12–15 chưa chạy, nên sau khi sửa phải tái chạy toàn bộ đúng case/tag để xác nhận database state, callback Scheduled và quota reallocation.

### Mở rộng phạm vi đã xác nhận

Người dùng xác nhận mở rộng request từ sửa assertion testcase sang bổ sung khả năng đọc Redis Stream MTC để lấy `MtcNewsletterId`. Contract đã chốt:
- Stream SB → MTC: `stream:BookingCampaignDispatchSliceStreamMessage`.
- Stream MTC → SB: `stream:BookingCampaignCreateStatusMessage`.
- Prefix môi trường local hiện tại: `sb_hau:`.
- Tool-QC dùng consumer group riêng, không dùng chung `sb-booking-hau`, để không tranh message với worker SB.
- Payload stream nằm trong field envelope `payload`; message MTC được correlate bằng `CampaignId` và `IdempotencyKey`, yêu cầu `Status = 1`, rồi save `MtcNewsletterId`.
- Nếu cấu hình Redis Stream chưa có trong `.env`, bổ sung local; `.env.example` chỉ ghi key và placeholder an toàn, không ghi connection string thật.

### Kiến thức bổ sung

Shared Redis executor hiện chỉ hỗ trợ `get`, `hget`, `set`, `delete`, `exists`, `xadd`; chưa hỗ trợ đọc stream, consumer group, lọc JSON payload hoặc save JSON path. Backend tạo key bằng `Prefix + "stream:" + type name`; do đó stream callback đầy đủ là `${REDIS_STREAM_PREFIX}stream:BookingCampaignCreateStatusMessage`, ví dụ `sb_hau:stream:BookingCampaignCreateStatusMessage`. Envelope Redis có field `payload` chứa JSON callback.

Thiết kế chọn consumer group riêng `tool-qc-be-booking`; consumer nhận tên duy nhất từ testcase/runner. Executor cần bảo đảm group tồn tại ở vị trí phù hợp để đọc message mới và không ACK message không khớp trước khi tìm đúng correlation. Cần unit test cho key building, envelope parsing, correlation và save `MtcNewsletterId`, cùng validation cho các tham số stream bắt buộc.
